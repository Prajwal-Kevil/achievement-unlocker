# Ethical contribution workflow

Achievements should be a by-product of useful work, not the goal of empty activity. This repository recommends the following workflow for anyone practicing GitHub collaboration:

1. Pick a documentation, accessibility, test, or maintenance improvement that a real reader would value.
2. Open an issue when the change benefits from discussion, or explain the scope directly in the pull request.
3. Use a focused branch and a descriptive commit message.
4. Run the checks documented by the project before requesting review.
5. Write a pull request description that explains what changed, why it matters, and how it was verified.
6. Credit real collaborators accurately. Never invent a co-author or use another person's identity without permission.
7. Merge only after the repository's review and CI expectations are satisfied.

For this guide, good contributions include correcting outdated requirements, improving source links, clarifying safety boundaries, and adding examples that help new contributors participate responsibly.
